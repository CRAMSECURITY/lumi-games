# LUMI 015.0 — RELEASE CANDIDATE

Кандидат для закрытого тестирования. Публичный запуск НЕ одобрен. Основа: 014.5 FINAL QA. Код приложения, дизайн, возрастные ограничения и миграции не менялись.

## 1. Локальная проверка (Windows)
1. Распакуйте в новую папку. Не заменяйте действующий проект.
2. До добавления .env и базы запустите `python 04_TOOLS/master_quality.py`.
3. Для предпросмотра нажмите `01_PREVIEW.bat`. Это не настоящий Telegram.
4. Для локального набора проверок: `python 04_TOOLS/release_gate.py --offline`. Код 2 означает успешные локальные проверки без разрешения релиза; код 1 — ошибка.

## 2. Закрытый тестовый сервер
- Сохраните старый проект, конфигурацию, SQLite и D1; проверьте восстановление. Не используйте реальную базу для тестов.
- В отдельном Python-окружении установите зависимости `python -m pip install -r 01_BOT/requirements.txt` и инструмент `pip-audit`. В `02_MINI_APP` выполните `npm ci` после проверки доверия к источникам. Запустите `06_RELEASE_GATE.bat` до добавления личных файлов. Даже код 0 не означает разрешение публичного запуска.
- Используйте отдельные тестовые токены основного и административного бота. Существующий wrangler.jsonc содержит старое имя Worker и идентификатор D1; перед любым развёртыванием замените их на отдельные тестовые ресурсы. Не выполняйте deploy с исходными настройками.
- Настройте `01_BOT/.env`: BOT_TOKEN, LUMI_ADMIN_BOT_TOKEN, LUMI_ADMIN_IDS, LUMI_GAMES_URL (HTTPS), LUMI_ENV=production, LUMI_BACKUP_KEY (Fernet), LUMI_BAN_SYNC_KEY (отдельный случайный секрет). Не пересылайте секреты и не кладите их в ZIP. Сохраните ключ резервного копирования отдельно. Для существующих копий нужен исходный ключ.
- В тестовом Worker установите BOT_TOKEN и тот же LUMI_BAN_SYNC_KEY. Примените все миграции D1 0001–0005 по порядку через Wrangler, только к тестовой базе. Проверьте /api/health. 
- Из 01_BOT запустите `python lumi_preflight.py` и `python lumi_preflight.py --role admin`. Затем в отдельных терминалах `python bot.py` и `python lumi_admin.py`. Не запускайте одновременно старый и новый экземпляры с одинаковыми токенами.

## 3. Обязательные критерии допуска
Все пункты ниже ещё требуют подтверждения на тестовой инфраструктуре. Зафиксируйте результаты, дату, окружение и доказательства в отдельном отчёте.
- [ ] Онлайн-аудит npm и Python; точные версии и воспроизводимые зависимости; устранение существенных CVE.
- [ ] Telegram: регистрация, анкеты, знакомства, чат, блокировки, жалобы, верификация, подарки, приглашения, дуэли, Premium, экспорт и удаление аккаунта.
- [ ] Android/iOS/Desktop: все кнопки и переходы, WebGL, сенсорные жесты, отсутствие зависаний и переполнения, измерение FPS, времени загрузки и памяти.
- [ ] Платежи Stars: успешная оплата, повторы, задержанные события, возвраты, сверка начислений в разрешённой тестовой среде.
- [ ] HTTPS/TLS, CSP, права доступа, отзыв сессий, синхронизация блокировок и удаление при сетевых сбоях.
- [ ] Нагрузочные испытания на собственном тестовом окружении с контролируемыми лимитами и измерением задержек, ошибок и ресурсов.
- [ ] Проверка шифрования рабочей SQLite и D1, защиты ключей, политики хранения и восстановления обеих баз.
- [ ] Внешние оповещения, восстановление процессов и резервных копий, план ручного отката с учётом совместимости миграций.
- [ ] Независимый авторизованный пентест и повторная проверка исправлений. Возрастные настройки не менялись; остаточные риски приложения знакомств 18+ требуют оценки владельцем.
- [ ] Подпись итогового архива постоянным ключом владельца; публичный ключ проверяется по независимому доверенному каналу.

Не восстанавливайте старую базу поверх работающей; согласуйте очередь блокировок с D1.
