# 023.6 BUSINESS MODERATION
Apply 0009_business_moderation.sql after 0008 before enabling the directory. Test on staging only. Existing approved profiles are preserved. Set LUMI_BUSINESS_MODERATION=1 and LUMI_BUSINESS_MODERATOR_IDS to a comma-separated list of trusted Telegram numeric IDs in server configuration; never put it in frontend code. Directory must also be enabled. Moderator must use their own authenticated LUMI session (x-lumi-session header); ordinary users cannot access these routes. Do not copy tokens into shared logs or chats.

GET /api/business/moderation/queue returns at most 50 pending profiles and 50 unreviewed reports. POST /api/business/moderation/decide accepts {revision,decision} where decision is approved or rejected. A changed or previously decided revision returns 409. Self-approval/rejection is forbidden. POST /api/business/moderation/review accepts {invite_id,reporter} and marks a report reviewed; no automatic sanctions. Participants cannot review their own reports or reports against themselves. Moderator response contains internal report participant identifiers; restrict access. Rejected users see a rejection status and may resubmit. Existing report retention remains 90 days. No moderator GUI, pagination, persistent moderator audit log, automated sanctions or identity verification. No age changes. Local Node test suite 77 tests; real Telegram/D1, Python regression and live security audit not run. Owner signature required. Next: live event catalog and organizer submissions.
