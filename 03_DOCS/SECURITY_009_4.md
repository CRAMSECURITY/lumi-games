# LUMI 009.4 DATABASE VAULT
База: 009.3. Общий модуль 01_BOT/lumi_database_vault.py используется основным и административным ботом, включая проверку блокировки и источник резервных копий.
- SQLite: secure_delete=ON, trusted_schema=OFF, temp_store=MEMORY. На POSIX umask 077 при старте, база создаётся с правами 0600; существующие база и WAL/SHM/journal ограничиваются до 0600. Отказ от файлов-ссылок и специальных файлов.
- Удаление аккаунта теперь также удаляет arena_intro.
- Исправлена изоляция теста отката экономики: общий тестовый monkeypatch закрывал соединение раньше проверки отката; используется обычный factory SQLite.
- 4 новых теста: существующие записи и PRAGMA, права WAL/SHM, ссылки, удаление маркера из тестовой базы. Общий Python offline suite: 62 теста, OK. Mini App: 35 тестов, OK. Синтаксис 35 Python файлов.

## Обновление
Остановить оба бота, сохранить проверенную зашифрованную резервную копию (ключ отдельно), сохранить .env и существующую lumi.db, обновить исходники обоих ботов вместе. Не удалять WAL/SHM вручную. Миграция D1 для 009.4 не нужна; ранее обязательные миграции по-прежнему нужны. Сначала тестовая копия.
На Linux разместить проект и данные в каталоге, доступном только выделенной учётной записи службы (режим 0700, без записи для посторонних). На Windows ограничить NTFS ACL каталога проекта и резервных копий учётной записью службы и доверенными администраторами, включить BitLocker или другое управляемое шифрование диска. Права POSIX не заменяют NTFS ACL. Проверить права также у .env, старых резервных копий и логов. Не хранить данные в публичной папке, облачной синхронизации или репозитории.

## Ограничения
Это не шифрование основной SQLite или D1. secure_delete не гарантирует удаление исторических данных из WAL, старых бэкапов, файловой системы/SSD и Telegram. Права файлов не защищают от компрометации самой учётной записи службы; проверки ссылок предполагают доверенный родительский каталог, не гарантируют защиту от гонок при доступе атакующего к каталогу. temp_store=MEMORY и secure_delete могут увеличить расход памяти и I/O; реальные замеры не проведены. Windows ACL, действующий Telegram, Cloudflare, aiogram runtime не проверены. Для шифрования рабочей базы нужна отдельная миграция (например SQLCipher после проверки совместимости) или шифрование тома; ключи отдельно. Не заявляется полное соответствие GDPR или полное удаление данных.
