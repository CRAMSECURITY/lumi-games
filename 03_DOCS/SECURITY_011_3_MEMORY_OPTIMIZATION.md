# 011.3 MEMORY OPTIMIZATION
Based on 011.2. Added bounded per-user sliding windows with ordered expiry for bot rate limiting and operations monitoring. Each rate limiter admits at most 10,000 tracked users, monitoring at most 5,000; new rate-limit identities are denied when full, active windows are not evicted. Monitoring skips per-user tracking when full but retains aggregate update/error counters. Expiry is lazy on subsequent traffic, not a periodic background job. Limits are per process, not distributed; sustained saturation may deny legitimate new users and reduce telemetry coverage. Existing 25 events/20 s and 120 events/600 s thresholds retained. No UI, schema or secret changes. Four new tests include 10,000 rejected identities, capacity reclamation and active-window preservation. 37 selected Python and 59 Node tests passed. Python syntax checked. FSM storage, browse history, teaser tasks and production RSS/latency remain unverified/unbounded by this patch. Full aiogram integration and staging load tests remain required.
