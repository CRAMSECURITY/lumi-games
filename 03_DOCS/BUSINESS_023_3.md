# 023.3 BUSINESS DISCOVERY — pilot

Disabled by default. Apply D1 migration 0006_business_directory.sql before enabling LUMI_BUSINESS_DIRECTORY=1 in the staging Worker environment. Do not enable on production until moderation, privacy and real Telegram checks are complete. Existing Telegram session and API rate limits are reused. The directory is visible to authenticated unblocked Mini App users, not only registered dating profiles; no additional age verification was added. Submission requires explicit consent. Each edit resets approval. Only approved cards are listed (maximum 20; goal filter), with no Telegram IDs, revision IDs or contact buttons. Contact-like patterns are rejected heuristically; human review is still necessary. Withdrawal deletes the record; account deletion inserts a receipt whose trigger deletes the profile. Banned profiles are hidden. Existing data in backups is subject to existing retention rules.

Manual moderation only: authorized infrastructure operator reviews the current row in D1, including its revision, and approves only that exact revision using a parameterized UPDATE business_profiles SET approved=1 WHERE user_id=? AND revision=? AND approved=0. Never expose the database console to ordinary moderators or users. No moderation UI, reporting, messaging or real-world events yet. To reject, leave unpublished; remove inappropriate records via authorized administration. Add a proper moderation workflow before public launch. No automatic expiry of pending submissions is implemented. A request already in flight can finish around a withdrawal; no absolute instantaneous revocation guarantee. No external trackers or external AI. No change to age rules, Python bot or existing artwork.
