# 013.3 — Disaster recovery rehearsal
Stop services before any real restore. Keep the active database and its WAL/SHM together; never delete sidecars to force a restore. Use an independently verified, compatible release and retain the current database snapshot before rollback. Run `python lumi_recovery_drill.py BACKUP PRIVATE_WORKSPACE` from 01_BOT with LUMI_BACKUP_KEY set securely in the environment. The workspace must exist, be private, and preferably reside on encrypted storage. The drill decrypts into a temporary directory, validates SQLite integrity, three essential LUMI tables and required column names, and foreign keys, then removes the temporary files. It does not prove complete schema compatibility or securely erase disk blocks; it never replaces the live database. Restore refuses existing database or sidecar files. Use the existing restore tool to recover to a new path only. D1 recovery, migration rollback, production drills and automatic service switching remain manual/unverified. The archive is unsigned until signed with the owner's pinned key.
