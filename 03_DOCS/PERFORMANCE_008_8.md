# LUMI 008.8 PERFORMANCE & PRIVACY

Основа: 008.7 SECURITY CORE. Дизайн и графические файлы сохранены.

## Производительность
- Модель приветствия kigurumi.glb (7,3 MiB) не скачивается при включённом Save-Data или reduced-motion; в остальных случаях загрузка начинается после двух кадров, с постером на экране. Размер модели не изменён.
- Скрипт 3D коллекции загружается по требованию с повторной попыткой при ошибке.
- Обработка pointermove для главных карточек и арены объединена по кадрам. Приветственная модель в покое рисуется примерно 30 раз/с, при перетаскивании — с частотой экрана. На устройствах с deviceMemory <= 4 снижено разрешение canvas.
- При скрытии страницы приостанавливается анимация парящих карточек; существующая остановка WebGL и опроса комнат сохранена.
- HTML no-cache, GLB cache 86400 секунд; проверить фактические заголовки после развёртывания.

## Безопасность
- Permissions-Policy запрещает камеру, микрофон, геолокацию, захват экрана, USB, serial, браузерный Payment Request API и датчики движения. Telegram-нативные платежи и разрешения необходимо проверить отдельно; политика не регулирует разрешения самого Telegram или загрузку фото через чат.
- CSP: удалён unsafe-inline для script-src; встроенный блок разрешён точным SHA-256. Обработчик onclick перенесён в JS. При изменении встроенного блока обновлять хеш в public/_headers. Внешний официальный скрипт Telegram оставлен; inline CSS разрешён для текущего дизайна.
- Шифрование копий SQLite: Fernet (аутентифицированное шифрование), отдельный ключ, снимок в памяти без промежуточного незашифрованного файла. Старые копии автоматически не шифруются. Основная SQLite и D1 этим изменением не шифруются. Для основной базы нужна отдельная миграция/шифрование диска, для D1 — проверка настроек провайдера и модель угроз.

## Включение шифрования на сервере бота
Python 3.11+ со сборкой SQLite с поддержкой serialize; обновить зависимости из 01_BOT/requirements.txt. В каталоге 01_BOT выполнить локально:

    python -c "from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())"

Сохранить результат в секретном окружении сервера или локальном .env, не в ZIP, не в Git и не в переписке:

    LUMI_BACKUP_KEY=<сгенерированный ключ>
    LUMI_REQUIRE_ENCRYPTED_BACKUP=1

Ключ хранить отдельно от резервных копий. Без ключа прежний режим остаётся для совместимости и выдаёт предупреждение; при REQUIRE=1 отсутствие ключа блокирует резервное копирование/запуск при наличии БД. Неверный ключ вызывает ошибку. Потеря ключа означает потерю доступа к зашифрованным копиям. Сделать тест восстановления до обновления production.
Восстановление: остановить бота, сохранить действующую БД, расшифровать копию в отдельный защищённый файл через lumi_backup_crypto.decrypt_snapshot(payload, key), выполнить PRAGMA integrity_check, затем заменять БД только после проверки. Не перезаписывать рабочую БД автоматически. Снимок хранится в RAM, поэтому для больших баз требуется потоковая схема или отдельный сервер резервного копирования.
