# 017.1 — Event analytics prototype
Separate SQLite store, not wired to production. Call init once; record with server-derived user ID, allowlisted event and UTC date; use an externally stored random key of at least 32 bytes. Keep the same key for the entire retention period. Never expose a public ingestion endpoint without authentication. Call erase on account deletion and prune daily; these calls are not yet scheduled. Store with restricted permissions and encrypted backups. HMAC identifiers are pseudonymous personal data, not anonymous. Coverage start is operator-supplied and assumes uninterrupted collection; gaps must be tracked before production. DAU/WAU/MAU refer only to recorded events, completed UTC days. D1/D7/D30 are exact-day returns for the cohort whose target day was yesterday; deleted subjects are excluded. Signup must be emitted only once per account lifecycle by the integration. No revenue estimates from event data. No bot integration or deployment yet.
Tests: cd analytics; python -m unittest -v test_lumi_events test_lumi_growth
